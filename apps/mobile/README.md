# EDP mobile

One Flutter app with English/Tamil public CMS and resources, account/session controls, applicant intake/documents, student learning/schedule/attendance, mentoring, business plans, funding, helpdesk, private alumni profiles/follow-ups, self-reported impact and enrollment updates. The applicant, assignment and helpdesk file panels use bounded private copies, scan/readiness and verified download receipts. Session credentials remain in the central identity repository; selected documents and consequential commands have no durable offline queue.

The native Android/iOS private-file adapters require platform compilation and device acceptance; Dart/API tests do not establish provider-URI, secure-storage, process-death or protected-storage behavior. See [M02 implementation](../../docs/architecture/mobile-private-files.md) and [native file acceptance](../../docs/testing/native-file-acceptance.md). Web compilation is a check, not a supported private-file runtime.

With the supported Flutter SDK, run `flutter pub get --enforce-lockfile`, `flutter gen-l10n`, `flutter analyze` and `flutter test`. In this workspace the cached SDK is `.tool-cache/flutter` and package cache is `.tool-cache/pub`; set `PUB_CACHE` to that cache and add `--offline` for cached lock enforcement. Opt-in real API checks run from the repository root with the supported Python environment: `python scripts/run-mobile-api-tests.py --slice m00`, `--slice applicant`, `--slice documents`, `--slice learning`, `--slice support` or `--slice alumni`. Alumni also has `python scripts/run-mobile-alumni-tests.py`. The runners use only guarded synthetic loopback fixtures and dedicated mobile databases, and clean up their owned processes and credential files. Controlled file scanning in these tests is not real ClamD/queue evidence.

Open an organization's learning, mentoring, support, resources, business or updates link after sign-in. Server ownership/enrollment checks remain authoritative. A completed alumnus can retain the business/helpdesk/history access allowed by the API; active-enrollment business-plan and private funding controls never bypass a rejected API response. Public resources remain available without sign-in.

Attendance supports manual entry and an explicit camera action. Android delegates QR capture to Google Play services (`play-services-code-scanner:16.1.0`), which may need its optional module downloaded on first use. iOS uses AVFoundation and requests camera access. A scan only fills a validated `edp-attendance:` code; review it and press **Check in** separately. Denial, missing services, invalid codes or camera failure retain manual entry. Native source is subject to the [attendance device matrix](../../docs/testing/native-attendance-acceptance.md).

Internal links accept only the documented relative routes and bounded identifiers: `/applications`, `/learning?organization=UUID&course=UUID&lesson=UUID`, `/support?organization=UUID&ticket=UUID`, `/alumni?organization=UUID&enrollment=UUID&follow_up=UUID`, `/updates?organization=UUID`, `/resources?organization=UUID&item=UUID` and `/certificate?code=CODE`. Object links re-read current owner/public APIs; foreign URLs, token parameters and inconsistent parents are rejected. These routes do not establish Android App Links or iOS Universal Links; owned-domain association remains a release task.

`GET /public/mobile-policy?platform=android|ios|web` supplies optional public update metadata. Set `--dart-define=APP_VERSION=0.1.0` to the release's actual semantic version alongside its build name. The default matches `pubspec.yaml`. Disabled, missing, offline or invalid metadata leaves the app usable. Valid native metadata shows a localized update prompt and only its configured HTTPS download destination; the app does not invent store links. A minimum-version prompt remains visible while retaining the current workspace and entered text.

See [mobile architecture](../../docs/mobile/mobile-architecture.md), [local setup](../../docs/deployment/local.md), [native acceptance](../../docs/testing/native-session-acceptance.md), the current [baseline verification plan](../../docs/sdlc/baseline-verification-plan.md) and its [verification report](../../docs/sdlc/baseline-verification-report.md). Local web/API acceptance does not close the native-device gates. Platform identifiers `com.example.edp_mobile` are development placeholders, not approved store identifiers.
