## Slice M00: session, navigation and domain client foundation

Keep the feature-first layout and existing libraries. Introduce a small `core/api` transport/error layer, a central session controller and a navigation shell; give each feature typed models, a repository and Riverpod state. Avoid a generic form/workflow engine or one large dashboard repository. Page state and unsaved inputs belong to the feature and are disposed on logout or organization change.

1. Extend the typed profile to consume `Profile.locale` and `Grant.organization_id`, `organization_name`, `permissions` from `GET /api/v1/auth/me`. Restore once at application/session lifecycle entry; distinguish restoring, signed out, authenticated and temporarily unavailable states. A transient read failure must not invent a signed-in profile or display another user's cached data.
2. Extract authenticated JSON and bounded-byte operations behind one session-aware transport. Keep one refresh operation shared across concurrent requests and propagate session invalidation centrally. Public repositories must not accidentally attach authorization. Never persist access tokens/passwords or expose the refresh token to feature code.
3. Automatically retry only bounded safe reads where appropriate. A 401 may trigger the serialized refresh, but consequential writes are not automatically replayed. After authentication recovery, re-read the relevant domain state and require an explicit decision before retrying an uncertain write. Respect `Retry-After`; distinguish offline/timeout, expired session, forbidden/not found, validation, version conflict and unavailable dependencies using stable localized error codes. Do not log authorization, reset/verification tokens, attendance tokens, material capabilities, document names or form/message bodies.
4. Provide an account/application destination for every authenticated user, including an applicant with zero grants. Organization destinations come from current server grants and owned application history, not a locally selected role. `participant.self` and `lms.learn` can inform navigation, but the relevant domain response remains authoritative for enrollment/object access. Keep explicit organization context when switching modules and clear prior results before loading a different context.
5. Use a compact guest shell for program information/content, resources/opportunities and account. Authenticated home shows available destinations and bounded independently loaded summaries: application status, program schedule/learning, support and business/outcome work when supported. A failed summary must not prevent other authorized destinations from opening. Do not fabricate dashboard totals or add a dashboard API solely to concatenate existing responses.
6. Complete editorial list pagination, localized kind titles, full details, empty/error/retry states and stale-response protection. Make the existing news/event/FAQ/testimonial routes discoverable. Public enquiries follow the existing localized policy endpoint: absent approval/configuration means no collection form. The current app-version endpoint and push-device registration are absent; do not claim forced updates or push support.

Acceptance: concurrent protected reads rotate refresh once; refresh timeout clears the possibly consumed token; revoked sessions clear domain state and pending destinations; offline logout clears local credentials and reports unconfirmed server revocation. Zero-grant applicants can reach history/intake. Multi-organization navigation never renders prior-organization data as the new organization. Guest and authenticated shells pass English/Tamil widget/navigation tests, semantics checks, small-screen and large-text review. Preserve existing identity tests.

## Slice M02: native secure-file transport and application documents

Create one bounded file transport with typed domain repositories, not a generic ownership API. Reuse it later for assignment/helpdesk files while keeping their policy, revision and authorization rules separate.

Continuation checkpoint (2026-10-24): finish the existing partial Dart/Android implementation, add the matching iOS adapter and connect a bilingual document panel to the owned applicant editor. Document commands and scalar commands must be serialized; acknowledged document versions refresh the exact application while preserving dirty answers. Fence late picker responses when backgrounded, enforce both pinned requirement and policy counts, and verify lost-response recovery with real loopback API operations plus deterministic adapter/controller/widget checks. The first download UI is a verified private receipt with explicit deletion; it introduces no document parser or export. Record Android/iOS compilation and device execution separately from Dart/API evidence.

List-bound refinement (2026-10-24): owner and reviewer document lists already exclude removed bindings before cursor pagination. Replacements always set `removed_at`, and a database constraint prevents a replacement pointer without removal. Historical replacement volume therefore does not justify an `active_only` API extension. The actual client-bound gap is that a form may pin up to 20 document requirements with up to 100 files each; reconcile bounded pages against the pinned aggregate allowance, with a hard 2,000-item ceiling, rather than an invented 100-item application total. Add a backend regression for replacement/removal exclusion, cursor validity and owner/organization scope. Preserve the existing API shape, contract and migrations.

1. Show collection availability, pinned bilingual notice, supported MIME types, file/count limits and retention details before picking a file. Effective limits are the lower of policy and current operational ceilings; the schema's 100 MiB maximum is not permission to upload that size. Disabled collection provides no picker/byte controls. A missing/retired policy or unavailable scanner must not appear as successful collection.
2. Use a platform file picker with only required access. Treat provider URIs as untrusted; snapshot the selected stream into bounded app-private temporary storage when needed, count/hash those exact bytes and register their size/MIME/SHA-256. Avoid loading the maximum allowed file fully into memory. Never delete the user's original selected file or upload local paths, storage references or unnecessary filenames. A changed provider file must be rejected or reselected as a new intent.
3. Preserve the exact `client_request_id`, request body and immutable selected-byte reference while the screen remains active. After an uncertain intent, explicitly recover that same request; changed reuse is a conflict. An acknowledged intent updates the application version without replacing scalar answers. Raw PUT sends exact MIME and a quoted positive file version in `If-Match`, with no multipart/Content-Encoding wrapper. The server independently verifies the actual bytes; a progress bar or completed PUT is not a clean scan.
4. Reconcile a lost PUT through the known typed detail before any explicit continuation. Quarantined/scanning states trigger bounded reads only; backgrounding pauses polling and resume refreshes state. Never resend bytes automatically on timeout, 401, rebuild or app resume. Only a server-authorized pending continuation using current version and the identical bytes may be attempted explicitly; an in-progress lease, rejection or new revision cannot be bypassed.
5. Use `usable` plus required counts to display readiness; `clean` alone does not satisfy current retention/proof rules. Handle replacement as a fresh immutable binding, explicit removal and scan-unavailable/infected/rejected/deleted states. Submitted views show frozen file version/hash/size/date even if operational file versions later advance.
6. Each download requests the typed endpoint again with current bearer authorization. Bound response bytes, prevent credential forwarding across redirects/origins and stage only in app-private temporary storage. Do not pass bearer tokens or material capabilities to arbitrary external viewers. Sharing/export requires an explicit user action and policy-compatible design; previously exported bytes cannot be recalled by later server revocation.
7. Initial implementation has no durable offline document queue. On process death, discard in-memory selected-byte references and reload authoritative owned bindings; allow explicit re-selection only after matching the registered byte proof and current state. Never claim an ambiguous registration was recovered merely from a filename. If persistent recovery metadata becomes necessary, specify its minimal fields, secure storage, expiry and cleanup separately before implementation; do not silently retain applicant documents.

Acceptance: test each allowed synthetic format, zero/over-limit/mismatched bytes, checksum/type failures, read-before-resend, changed UUID reuse, stale versions, scanner unavailable/unsafe, policy retirement, unusable clean/expired files, replacement/removal, process interruption and session revocation during upload/download. Assert one byte write during lost-response recovery, no submission before required evidence is usable, immutable evidence after submission, peer/organization denial and immediate denial of a new download after access revocation. Real file-picker/provider-URI/temp-file behavior needs Android/iOS execution; deterministic adapter/widget tests do not close it.

## Deep links, localization and offline/privacy rules across slices

**Deep links.** Define a small typed internal destination set for account/apply/application, course/lesson, attendance, support ticket, public resource/certificate and business/outcome entries. Parse bounded IDs/enums and retain only the minimum validated pending destination across login. Opening a route performs current session/object authorization; a URL/notification role label never supplies access. Reject foreign origins, unsupported schemes, traversal, repeated/unknown sensitive parameters and arbitrary redirect targets. Never put access/refresh credentials or applicant answers in links. Verification/reset token links need separate approved handling and redacted diagnostics; keep current manual token entry until implemented safely. Android App Links/iOS Universal Links need owned-domain association and approved identifiers; routing unit tests alone do not establish OS link activation. FCM/device registration and push-tap acceptance are added only if step 3 supplies approved server/device contracts and configuration; otherwise record them deferred and keep in-app refresh usable.

**English/Tamil and accessibility.** Add keys to ARB sources and regenerate localization outputs; never edit generated Dart localization files. Localize states, errors, notices, tabs, field labels, empty/loading/retry and confirmation text, including raw server enums. Preserve user-entered language and server edition text; no invented fallback consent. Test key/placeholder/plural parity, Tamil wrapping, 320/360/390 logical-pixel widths and tablet layout, large text, focus order, semantic labels/live updates, keyboard navigation where supported and contrast/touch-target review. Use locale-aware date/number presentation without shifting date-only fields through UTC conversion. TalkBack/VoiceOver and system text scaling need native evidence.

**Offline and local storage.** Start with bounded in-memory read models and an explicit unavailable/stale state, manual retry and preserved current-screen input. Server-saved drafts are restored by authenticated reads, not a hidden local form database. No offline write queue for submissions, attempts, attendance, funding, messages or outcomes. Never cache passwords/access tokens, private documents, material capabilities, ticket/mentor prose, application answers or private outcome data in ordinary preferences, browser storage, analytics or crash payloads. Refresh stays in the existing secure store. Persistent read-only caching may later cover explicitly approved public content; define per-type expiry/size/version, visible stale/offline status and revalidation before enabling it. Private learning/offline downloads require a separate approved content/privacy policy; the first slice must not infer approval from the master architecture's eventual offline capability.

**Lifecycle.** Clear scoped state on logout, user/organization change and revocation. Pause polling in background and revalidate on resume. Delete app-created temporary bytes on success/cancel/logout and perform bounded cleanup of abandoned app-owned temporary files on startup; do not touch source documents outside app storage. OS backup exclusions, iOS data protection, interrupted downloads, viewer behavior and cleanup after process death require native tests and policy review. No claim of remote deletion can recall bytes deliberately exported by the user.
