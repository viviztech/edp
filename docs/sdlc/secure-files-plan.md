## Foundation contract

- Purposes: `application_document`, `cms_asset`, `assignment_submission`, `lms_material`, `helpdesk_attachment`. Every file has an organization, owner, trusted domain context and pinned policy edition. Later domain bindings use typed tables and organization-aware foreign keys; no generic browser-controlled resource reference grants access.
- A normalized client request UUID provides idempotent metadata creation; changed reuse conflicts. Store opaque generated object keys, expected media type/size/hash, actual verified size/hash and immutable storage version. Never expose keys, bucket paths, scanner credentials or capability secrets in DTOs/logs/audit.
- Lifecycle: pending metadata, fenced upload, quarantine, leased scanning, clean/infected/rejected, and disposed bytes. The exact state names may follow the implementation, but clean requires verified completion and a scan of those same immutable bytes. Unknown, failed or unavailable scanners never mark a file clean.
- Only dedicated, authenticated and domain-authorized byte routes may bypass existing JSON caps. Stream/count real bytes independently of Content-Length; reject unsupported encodings, type/signature mismatches, hash mismatches, excess size and replay/overwrite attempts. Keep metadata commands bounded. Preserve BFF origin/CSRF checks and closed route/query allowlists.
- Use a confined local adapter for synthetic local/test work and an S3 adapter with conditional writes, private versioned objects, verified checksums and pinned-version reads/deletion. Store providers/bucket configuration on the server. No real provider calls or credentials in tests.
- Initial adapter names: `StoredObject(key, version_id, media_type, byte_size, sha256)`, `PrivateStorage.put/open/delete`, `StorageError(code)`; `ClamAVScanner.scan(source, max_bytes) → ScanResult(status, sha256, byte_size, reason_code)`. Adapters must bound all bytes/replies and total deadlines. Core services compare the scan digest/count with recorded verified bytes.
- Domain authorization is rechecked before delivery. Validate/copy the exact bytes to a private temporary snapshot before sending if necessary to avoid a verification/read race. Use safe download filenames, no-store, nosniff and controlled disposition. A transferable object-store URL must not bypass immediate reauthorization expectations.
- Published policies and verified object identities are immutable; replacements create new records. Scan workers use leases/fencing, bounded attempts/backoff and sanitized failure codes. Retention uses explicitly configured policy, honors legal holds and frozen domain evidence, and cannot delete arbitrary keys or an entire bucket. File metadata/audit retention and production deletion approval remain separate decisions.

Native document caching/security and device validation follow the Flutter process.

Reference implementation guidance: [S3 conditional/checksummed writes](https://docs.aws.amazon.com/boto3/latest/reference/services/s3/client/put_object.html), [versioned reads](https://docs.aws.amazon.com/boto3/latest/reference/services/s3/client/get_object.html), [ClamD protocol](https://docs.clamav.net/manual/Usage/ClamdProtocol.html), and [scanner operating boundaries](https://docs.clamav.net/manual/Usage/Scanning.html). ClamD TCP is unauthenticated; it must stay on a private trusted connection. An absent/failed/ambiguous response remains unusable.
