## Reporting contract

Organization-scoped `report.view`, `report.export` and `impact.manage` are distinct. Super Admin/Program Director have all three; Program Manager has view/manage without export. Other seeded roles receive no broad reports. A grant is explicit organization-wide reporting authority; cohort filters never confer authority. Dashboard and snapshot reads contain aggregates and definitions, never participant identities, notes, contact details, scores by person, attachment content or private reasons.

Authenticated base `/api/v1/reports/organizations/{org}`: GET `/options` (bounded program/cohort choices), GET `/dashboard`, GET `/definitions`, GET/POST `/snapshots`, GET `/snapshots/{id}`, GET/POST `/exports`, GET `/exports/{id}`, POST `/exports/{id}/access` and GET `/exports/{id}/download/{token}`. Required dashboard dates `from_date`/`through_date` are inclusive UTC calendar days, ordered, not future, maximum 366 days. Optional program/cohort must exist in the organization and agree. Do not silently truncate aggregates: use SQL aggregates and EXISTS/subqueries to prevent join fan-out; bounded grouping includes an explicit Other bucket when needed. Document a measured query budget and EXPLAIN evidence without asserting production capacity.

Dashboard groups cover marketing, program, learning, entrepreneurship, funding, support and impact. Each metric has a stable key, bilingual label/definition, source, temporal basis, unit, numerator, denominator, nullable value and applicability/data caveat. Zero denominator means unavailable, not zero percent. Distinguish dated events from current states of a date-selected population. The generated time is the current observation time; live current statuses are not historical as-of values for the period end. Use one coherent database read snapshot when persisting dashboard evidence.

Marketing covers lead source/campaign, attributable registrations, applications and linked funnel ratios. Lead/registration source counts and lead conversion are organization-only when unconverted leads lack reliable program/cohort attribution; filtered views say unavailable rather than fabricating allocation. Lead-to-application uses distinct non-merged leads created in the window and an actual LeadConversion/person/application link. Application-to-selection uses submitted-window applications and current selected/enrolled states; selection-to-enrollment uses their actual enrollment links. Never divide independently selected populations.

Program covers enrollments, active participants, withdrawn enrollments (not inferred dropouts), completed enrollments and certificates. Learning covers started/completed course enrollments, recorded lesson progress, quiz attempt results and assignment submissions/grades. Attendance is explicitly the rate among recorded present/late/absent marks (excused excluded), not assumed attendance for missing marks. Entrepreneurship covers idea-stage profiles, submitted/approved business plans, latest self-reported business outcomes, active/started businesses and jobs. Funding counts cases with applied/approval/disbursement evidence; exact funding facilitated is unavailable because transaction amounts are not recorded. Support covers tickets, first recorded resolution duration, mentor sessions and business/mentor follow-ups. Participant-linked support/funding scope uses EXISTS membership, counts each fact once and explains that membership is not causal attribution.

## Minimal impact evidence

Authenticated `/api/v1/impact/organizations/{org}`: GET/POST `/definitions`, POST `/definitions/{id}/publish` and `/archive`, GET `/mine`, POST `/records`. Prefix schema names with Report/Impact to preserve existing contracts. Staff create a new numbered immutable definition edition (bilingual title/definition, fixed structured enterprise measures: business_started, business_active, jobs_created), publish explicitly with a reason/version, and may archive it. No organization measurement policy or approved live definition is seeded. Participants see published editions and their own immutable earlier evidence, even after archival. Definition publication/content and observation corrections are versioned and database guarded.

`participant.self` plus the authenticated Person's active/completed Participant and active/completed owned Enrollment permits baseline/outcome recording independently of B02 BusinessProfile. Fields: enrollment_id, definition_id, stage baseline/outcome, observed_on, business_started, business_active, jobs_created (0..100000), expected_revision (0 for first), meaningful reason and client request_id UUID. Active implies started. No future dates, arbitrary staff proxying, free-form financial data or attachments. Record key is enrollment/stage/observed_on; corrections append sequential revisions and pin the definition edition. A correction cannot switch definition. Repeating a request UUID with identical normalized input returns the same record; changed reuse conflicts. Exact revision rejects stale writes. Scope, immutable evidence and identity are repeated by PostgreSQL.

Impact dashboard uses the latest revision per observation date, then latest baseline and latest outcome within the selected period per enrollment, with explicit reported/eligible coverage and matched-sample comparison only when baseline date is no later than outcome. Never sum repeated snapshots/jobs or double-count a person as an enrollment metric. Definitions/editions are visible, mixed definitions are separately grouped, and B02 outcomes remain a separate source so duplicate reports cannot inflate totals. No inferred lifecycle/causal impact or verified funding claim.

The reporting population contains all scoped enrollments recorded by the end-date boundary, including withdrawn enrollments; current eligibility governs owner writes rather than removing historical evidence. Coverage is reported enrollments divided by that reporting population. Source observations are selected within the requested period, and multiple edition groups never add their denominators to inflate the overall coverage. Excessive edition groups or oversized snapshot/export payloads fail explicitly with a narrower-filter request rather than silently dropping data.

## Snapshots and exports

`CohortImpactSnapshot` pins normalized filters, UTC generation time, metric dictionary version, measurement edition references and the complete validated aggregate response. Request UUID makes snapshot creation safe to recover. Snapshot rows are immutable and organization-scoped; they remain reproducible when source data changes. Read sensitive reports/snapshots and export requests/access/downloads audit identifiers and filter field names, with no observation values or prose in logs/audit.

Exports are durable bounded jobs over an existing authorized snapshot, aggregate-only CSV generated server-side (maximum 500 rows / 256 KiB). They may finish synchronously because output is bounded; this does not imply worker/provider execution. Separate view/export grants, requester ownership, reason, request UUID, per-job expiry and a newly issued short-lived authenticated capability are required. Reauthorize every access/download, bind token to job/requester, store only token hash and exclude tokens/CSV from metadata/audit/logs. Escape spreadsheet formulas in every untrusted textual cell. Download uses attachment/no-store/nosniff headers; fixed BFF preserves CSV bytes and rejects arbitrary paths/queries. No unbounded/raw participant export, public URL, XLSX/PDF or new dependency is introduced.
