# Milestone 9 / post-training and helpdesk acceptance

Recorded: 2026-10-21. Status: local web/API implementation and acceptance complete. Master Phase 9, R11/R16, B02/S01 and the [phase plan](milestone-09-plan.md) define scope. Native clients, remote CI and production release are separate gates.

## Delivered behavior

Participants and eligible completed alumni can create helpdesk tickets in nine categories, choose priority, add shared replies and download private plain-text attachments. Staff claim minimal unassigned records, work within their current assignment, hand over to eligible staff, change priority, request information, resolve and close tickets. Only the owner or organization admin can reopen a resolved/closed request, returning it to the unassigned queue while preserving evidence. Internal notes, their attachments and private staff reasons are excluded from owner responses.

Client request UUIDs make interrupted creation recoverable without duplicate tickets. Exact versions guard every subsequent ticket command. Immutable messages, assignments, history and attachments preserve evidence; PostgreSQL repeats lifecycle, ownership, assignment eligibility, required-history and append-only controls. Recipient-only in-app notices are transactional and deduplicated; preference opt-out and current owner/assignment authorization apply. Downloads, preference changes and read markers are audited without ticket text or filenames. No outbound email/SMS/push delivery is asserted.

The existing B02 module now has full phase-specific acceptance for private business profiles, immutable revisions, fixed periodic follow-ups and self-reported outcomes. Suspended/withdrawn participant access is denied even when an enrollment remains active; completed eligible alumni remain supported. UTC dates govern schedules/reporting. Required profile text and policy reasons normalize whitespace. Business forms freeze during writes, preserve separate follow-up drafts, apply authoritative outcome responses and require explicit refresh after uncertain/stale changes. Saved versions remain available for comparison without overwriting local input. English/Tamil value labels and visible responsive form controls are included.

The bilingual participant/staff helpdesk uses generated contracts, bounded pagination, fixed BFF routes, Origin/CSRF checks, streamed UTF-8 body limits, version recovery and private attachment transport. Navigation integrates both workspaces. Plain-text files are limited to three per message and 32 KiB each; binary, HTML/script, unsafe names and control payloads are rejected. Broader PDF/image/document ingestion remains the existing secure-file pipeline work.
