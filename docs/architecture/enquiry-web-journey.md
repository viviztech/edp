# Enquiry web journey

The public contact page `/{en|ta}/pages/contact` reads the backend enquiry policy without caching. The form is unavailable by default. Opening it requires `CONTACT_ENQUIRIES_ENABLED=true`, the current `CONTACT_PRIVACY_VERSION`, and approved notice URLs and consent texts for **both** English and Tamil (`CONTACT_PRIVACY_NOTICE_URL_EN/TA`, `CONTACT_CONSENT_TEXT_EN/TA`). Notices must use HTTPS without embedded credentials or a local `/{en|ta}/pages/{slug}` document path. The owner must approve and publish the actual notice, purpose, consent, retention and operational contact arrangements before collecting real enquiries. Configuration does not certify that approval or that a linked document exists. Automated local tests use explicitly synthetic consent only.

The form collects name, email, optional phone and a plain-text question, with explicit unchecked consent linked to the configured notice. It never accepts file bytes. A successful response displays only an opaque reference and removes the contact fields from the rendered form. An uncertain submission preserves input and retries only after an explicit user action; exact duplicate messages receive an indistinguishable accepted response without creating a second enquiry. An outdated policy locks submission until the page is reloaded and the current notice reviewed.

`POST /api/enquiries/public` binds the destination to server `PUBLIC_ORGANIZATION_ID`. It requires the normal anonymous CSRF cookie/header and configured Origin, rejects unknown/query parameters and a filled honeypot, decodes UTF-8 strictly and caps its body at 32 KiB. It rereads the current approved backend policy before calling `POST /api/v1/public/organizations/{org}/enquiries`. Only the allowed contact fields and current version cross that boundary. The server BFF key is never exposed to the browser; browser sessions, authorization and arbitrary forwarded IP headers are not sent through the public proxy. Responses contain only the accepted/reference receipt or fixed error codes.

The API independently enforces enabled policy/current consent, validation, a 32 KiB streaming bound and persistent 15-minute abuse budgets (30 attempts per connecting peer, five valid attempts per organization/email). Throttle keys are hashed using the existing authentication throttle infrastructure. Caller-supplied `X-Forwarded-For` does not influence the identity. Deployments where the BFF connects as a single peer share its source budget. A deployment-reviewed proxy identity contract is required before adding individual browser address attribution; bypassing the source budget is not an acceptable workaround. There is no outbound message/provider integration in this slice.

The staff workspace `/{en|ta}/admin/enquiries?organization={org}` requires `enquiry.view` within that organization. Its closed BFF allows only `GET .../enquiries/queue`, `GET .../enquiries/{id}` and `POST .../enquiries/{id}/status`. The queue accepts bounded UUID cursor/limit and new/reviewed/closed status filters; duplicate or unsupported parameters fail. Queue pagination is deterministic by UUID. The older API `GET .../enquiries` array remains available for existing consumers.

`enquiry.manage` additionally permits the explicit forward lifecycle `new → reviewed → closed`, with row locks and expected versions. Received contact content stays immutable. Status/version changes and minimal audit metadata commit together; audits omit names, contact fields and questions. Database guards enforce initial/versioned state and received-content immutability. Super Admin, Program Director, Program Manager and Support Executive receive view/manage through scoped role grants. Other roles gain no enquiry rights. The workspace has no internal-note editor or public staff-detail endpoint. An uncertain or stale command remains locked until details are explicitly refreshed; commands never retry automatically. Staff responses are private/no-store/noindex and escaped text is rendered without HTML execution.

Migration `g2c8d4e0f567` extends `f1b7c3d9e456`, backfills version/time without changing received content, and adds the queue index, lifecycle guard and permission. Downgrade discards only the new version/time metadata and management permission; run destructive migration rehearsals only on disposable test databases. Reverting code while keeping the additive schema is the preferred operational rollback.

Focused checks live in `apps/api/tests/test_enquiries.py`, `apps/web/src/lib/enquiry-security.test.ts`, public/staff enquiry BFF tests and the public/staff component tests. They cover configuration/consent gates, anonymous receipts/deduplication, UTF-8/size limits, abuse/XFF boundaries, role/organization negatives, cursor pages, concurrent stale commands, audit rollback and uncertain-response recovery in English/Tamil. Full process acceptance also requires integrated browser checks orchestrated by the milestone owner.
