# Flutter architecture

One app; feature-first directories, Riverpod for state, GoRouter for navigation, Dio repositories for API access. The shared domain client/session shell, public editorial/resources, applicant intake/documents, student learning/attendance, participant mentoring/plans/funding/helpdesk and alumni business/impact/updates are implemented. See [M03](../sdlc/flutter-m03-report.md), [M04](../sdlc/flutter-m04-report.md), [M05](../sdlc/flutter-m05-report.md), [domain client](../architecture/flutter-domain-client.md), [private files](../architecture/mobile-private-files.md) and the [slice plan](../sdlc/flutter-domain-plan.md).

Guest tabs Home/Programs/Opportunities/Resources/Account; applicant Home/Application/Updates/Resources/Profile; student Home/Learn/Opportunities/Support/Profile. Actual navigation follows server-authorized capabilities and enrollment state, never a locally chosen role. Mentor access pending policy.

The central session manager serializes refresh, uses OS secure storage for the refresh token and memory for the access token, revokes/clears on logout and surfaces expired sessions. Central error codes map to localized messages. English/Tamil ARB sources generate UI messages, supported server-state labels and field labels; date-only values remain dates and timestamps are presented locally. Typed relative links retain minimal validated context across login and re-read their exact authorized/public target. Environment/flavor contains the public API base and app version, with no provider credentials. Public app-policy metadata fails open when unavailable and uses only configured HTTPS download destinations. FCM and owned-domain OS link association remain deferred until approved configuration.

Read models are bounded in memory; public persistent caching and private offline downloads remain disabled pending approved expiry/content/privacy rules. Sensitive prose/files never enter ordinary preferences or browser storage. No offline write queue exists. Consequential operations execute once; unknown results retain input and require authoritative readback before another explicit command. Existing idempotent creation/impact contracts retain the same UUID and body. Screen state and in-flight private copies are discarded when the authenticated context changes.

Camera capture is a narrow native channel. Android uses Google code scanner 16.1.0 with Play services handling its camera UI; iOS uses QR-only AVFoundation output with camera permission and background cancellation. Flutter receives only a bounded attendance payload and requires a separate check-in action. Missing/denied scanner capabilities preserve manual entry. Camera/file/secure-storage behavior still requires the native acceptance matrices; Dart tests and a browser compilation cannot establish device behavior.

Flutter web builds are compile checks, not the supported secure-storage production channel; Next.js handles browser accounts. Native Android/iOS secure-storage and device tests remain required. On ambiguous refresh failure, clear the possibly consumed refresh token rather than replaying it. Logout clears local storage even if remote revocation cannot be confirmed; network failure is shown and other sessions can be revoked after reconnecting. Dart models currently implement the small generated OpenAPI subset manually; full Dart generator adoption remains pending evaluation.

Android manifest disables OS backup for application data so secure-storage credentials are not restored onto another device. Debug manifest alone permits cleartext traffic for the local emulator; release API configuration rejects non-HTTPS URLs. Current native adapter compilation and device lifecycle/secure-storage acceptance must be established on the final source. A historical baseline build is not current native evidence.

The [2026-10-23 baseline report](../sdlc/baseline-verification-report.md) records current available checks and unresolved dependency/CI gates. Phase 10's local web/API acceptance does not establish Flutter domain or native-device acceptance.
